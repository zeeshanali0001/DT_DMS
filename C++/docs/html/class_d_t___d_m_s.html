Detailed Description

template<typename T>
class DT_DMS< T >

The DT_DMS class is the general class of the Digital Twin Data-Models-Services (DT-DMS) framework.

A digital twin is a real-time virtual clone of an object, a process, an environment, a scientific instrument, a set of mechanisms or a complex system: the Twin of Interest (ToI). It relies on the dual pair real/virtual and a real-time communication process with the physical entity it refers to. The class holds the formal specification of a Digital Twin: 

DT = ⟨ D, M, S, μ ⟩

Key features of the class include:

  • D: the ToI data (Data::DT_Data), D = D_hist ∪ D_rt.
  • M: the models of the ToI (Models::DT_Model), M = M_desc ∪ M_pred ∪ M_presc.
  • S: the DT services (Services::DT_Service), S = S_moni ∪ S_pred ∪ S_diag ∪ S_opti ∪ S_cont, with s : M × Ω_D → Y_s.
  • μ: the model inference or data assimilation function (Mu::DT_Mu), μ : Ω_D × M → M.
  • It connects the Data, Models and Services of the Digital Twin and manages the information flow between them: μ observes every data source and updates every model, and each model notifies the services coupled to it.
  • The iterator design pattern over the data, the models and the services (begin…(), current…(), next…(), end…()).
  • Validity checks of the DT: services versus models, models versus data and data versus services (checkConsistency()).
  • The export of its own Data-Models-Services diagram in the Graphviz format (dumpGraphviz()).

The components are held by std::shared_ptr: data, models, services and μ are parts of the DT, which can share them with other objects (e.g., a service shares its model).

◆ checkModelsVersusData()

template<typename T>
bool DT_DMS< T >::checkModelsVersusData ( std::ostream & out,
double epsilon = 1e-3,
double bigM = 0.1 ) const
inline

Checks the fitting of the data versus the models: for every data source D_i and every model M_j that gives values in time (Models::DT_Model::evaluate), computes δ = |ω(t) − m(t)| over the real-time data of the source.

  • If δ < ε for every datum, the model fits the data very well.
  • If the mean of δ is greater than bigM, the model does not fit the data well and should be updated, re-parameterized or discarded.
  • Otherwise the fitting is acceptable.

Models that give no value in time are skipped.

Parameters
outwhere the report is written.
epsilonthe tolerance ε under which a datum is fitted very well.
bigMthe mean deviation M over which the model does not fit the data.
Returns
false if some model does not fit some data source.

◆ checkServicesVersusModels()

template<typename T>
bool DT_DMS< T >::checkServicesVersusModels ( std::ostream & out) const
inline

Checks the consistency of the services with respect to the models they are coupled to.

  • A coupled model must belong to M.
  • A prediction service coupled to a model needs a predictive model.
  • An optimization or a control service needs a prescriptive model (it cannot run without it).
  • Monitoring and diagnosis services can use any model, or none (data-driven services).
    Parameters
    outwhere the report is written.
    Returns
    true if every service is consistent with its model.
